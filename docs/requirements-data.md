# Requirements data: files and schema

Generated by `python3 scripts/build_requirements.py` from the catalog snapshot in `data/raw/catalog/`
(catalog year 2026-27). Follows section 1 and 2 of `docs/data-contracts.md`; fields marked "extra" are
additions consumers may ignore.

## Files

| File | Contents |
|---|---|
| `data/courses.json` | `[{id, subject, number, title, units, breadths[], attributes[], crossListed[]?, source?}]`. `source: "berkeleytime"` marks a course the current catalog no longer lists (from `data/raw/supplement/courses.json`; no breadth tags). `units` is a number, or `[min, max]` for variable-unit courses. No descriptions, to keep it small. |
| `data/course_details.json` | `{ "<course id>": {description, prereqs, offered?, formerly?, grading?, languageLevel?} }` |
| `data/subjects.json` | `[{code, courses, aliases[]}]`, e.g. `{"code": "ELENG", "aliases": ["EE", "EL ENG"]}` |
| `data/requirements/colleges.json` | `[{id, name, requirementGroupId, universityGroupId, url}]`, ids `LS CDSS COE HAAS CED CNR CHEM BSE` |
| `data/requirements/majors.json` | `[{id, name, degree, college, catalogCode, programType, requirementGroupIds[], collegeGroupId, universityGroupId, url, departments[], interests[], academicFocus[], aliases[]}]`. `aliases` are lower-case search shorthands ("cogsci", "eecs"). `programType` is `major`, `joint-major` or `dual-degree`. |
| `data/requirements/minors.json` | Same shape without `degree`, `college` and the college/university ids. |
| `data/requirements/groups/<id>.json` | One requirement group (below). Ids: `major-<slug>-<ba|bs>`, `minor-<slug>`, `college-<ID>[-variant]`, `university`. |
| `data/requirements/overrides/<groupId>.json` | Hand corrections applied at build time. |
| `data/requirements/REPORT.md` | Counts, warnings, and the groups that rely most on self-check rules. |

## A student's checklist

`groups[major.requirementGroupIds[*]]` + `groups[major.collegeGroupId]` + `groups[major.universityGroupId]`.
Use the major's own `collegeGroupId`: most majors share their college's default group, but a few
programs have their own college-level rules. A course may count toward the major, the college and the
university groups at once unless a requirement's notes say otherwise.

## Group

```jsonc
{ "id": "major-computer-science-ba", "title": "Computer Science BA", "kind": "major", // major|minor|college|university
  "source": ["https://undergraduate.catalog.berkeley.edu/programs/A5201U", "..."],
  "catalogYear": "2026-27", "catalogCode": "A5201U",          // extra
  "notes": ["General Guidelines ..."],                          // extra: the catalog's narrative text for the program
  "requirements": [
    { "id": "mathematics", "title": "Mathematics",
      "section": "Lower Division",                              // extra: the catalog block it sits in, for grouping in the UI
      "notes": "…",                                             // optional: caveats printed with the rule
      "overridden": true,                                       // extra: present when a hand override replaced the rule
      "rule": RULE } ] }
```

### Choices (concentrations, emphases, tracks)

```jsonc
{ "id": "major-data-science-ba",
  "choices": [ { "id": "domain-emphasis", "title": "Domain Emphasis", "pick": 1,          // optional
                 "options": [ { "id": "aerospace", "title": "Aerospace" }, { "id": "cognition", "title": "Cognition" } ] } ],
  "requirements": [
    { "id": "linear-algebra", "title": "Linear Algebra", "section": "Lower Division", "rule": RULE },       // for everyone
    { "id": "cognition-lower-division", "title": "Lower Division", "section": "Cognition",
      "choice": "domain-emphasis", "option": "cognition", "rule": RULE } ] }                                // only for that option
```

- A student completes `pick` options of each choice; show only the requirements of the chosen option(s).
  Requirements without `choice`/`option` apply to everyone.
- Ids are slugs, unique within the group; options are in catalog order. `title` is the noun to show
  ("Domain Emphasis", "Concentration", "Emphasis", "Track", "Specialization", "Cluster").
- An option may have no requirements ("No concentration", for optional concentrations).
- Nested choices are flattened: MCB options are emphasis/track pairs ("Immunology and Molecular Medicine: Track 2").
  A block shared by several options is repeated under each, with ids that start with the option id.
- `section` of an option requirement is the heading to show inside the option: the option title, or
  "Lower Division" / "Upper Division" where the catalog block says so.
- The decisions are in `data/requirements/overrides/choices.json`; REPORT.md lists them ("Programs with a choice").

### Overrides (`data/requirements/overrides/`)

`<groupId>.json`: `{"why", "source", "replace"?, "renameSections"?, "renameRules"?, "merge"?}`.
`replace` maps a requirement id to a new `rule`/`notes`. `renameSections` maps a catalog block name to the
heading to show. `renameRules` is `[{block, rule, title}]`. `merge` is `[{block, title, type: anyOf|nOf|allOf|pool, n?,
rules | parts: [{label, rules}], notesFrom?, notes?, keep?}]` and turns rows that are alternatives into one requirement.
Rows named "X: Option N" are merged automatically. `choices.json` is described in its own `_about`.

## RULE

```jsonc
{ "type": "course", "course": "COMPSCI 61A" }
{ "type": "allOf", "rules": [RULE, ...] }
{ "type": "anyOf", "rules": [RULE, ...] }                       // any one
{ "type": "nOf", "n": 2, "rules": [RULE, ...] }                 // any n of the sub-rules
{ "type": "filter", "count": 4, "filter": FILTER }              // at least `count` distinct courses matching
{ "type": "filter", "minUnits": 8, "filter": FILTER }           // at least `minUnits` units of matching courses (may combine with count)
{ "type": "units", "minUnits": 120, "filter": FILTER }          // total units; an empty filter means any course
{ "type": "manual", "text": "…", "mentionedCourses": ["…"] }    // stated only in prose: show as a self-check box
```

Sub-rules of a merged requirement carry an extra `label` ("Option 1", "A. Earth System Science") naming the alternative.

FILTER keys, all optional, combined with AND:
`courses` (explicit list), `subjects`, `minNumber` / `maxNumber` (numeric part of the course number),
`breadth` (one area name), `attribute` (one code), `exclude` (course ids).

## Course tags

- `breadths`: the registrar's approved seven-course breadth areas for the course. Names: `Arts & Literature`,
  `Biological Science`, `Historical Studies`, `International Studies`, `Philosophy & Values`,
  `Physical Science`, `Social & Behavioral Sciences`. A course with two areas can be used for either, not both.
- `attributes`: `AC` American Cultures, `AH&I` American History & Institutions, `ELW` Entry Level Writing,
  `RCA` / `RCB` Reading & Composition first / second half, `FL` foreign language at second-semester level or
  above, `UD` numbered 100-199, `HSS` humanities/social sciences for Engineering and Chemistry (derived:
  has one of the five humanities/social-science breadth areas, or is R&C or American Cultures).
- Cross-listed courses each have their own record and list each other in `crossListed` (always symmetric, and every member of a family lists all the others). A requirement
  that names one of them usually names all of them; when matching a transcript, treat cross-listed ids as the same course.

- C-numbered courses are cross-listed by definition. Where the catalog names no partner for one, a C-numbered course in another subject with the same title and units is linked as `crossListed` (not when more than 4 courses share the title, and never an undergraduate number with a 200+ number). REPORT.md lists these under "Cross-listings inferred".
- `units` is 0 for eight courses the catalog gives no credits for (AEROSPC 100, AMERSTD 39, ENVDES 193, LANPRO 100A/100B/150A, MILSCI 1, PERSIAN 190); read 0 as "not stated".

## Same class, other number (`sameAs`, `retired`, `popularity`)

- `sameAs` lists the other ids of the same class: `MATH 1A` <-> `MATH 51`, `EECS 16A` = `ELENG 16A` = `ELENG 66`, `STAT 88` = `STAT C88S` (+ cross-listed `DATA C88S`). It is symmetric and closed per family and never repeats an id that is in `crossListed`; the full family is the two lists together.
- Evidence, in order: the catalog's "Formerly ..." field (skipped when one old number is claimed by several classes, or when the old number now belongs to a class with a different title, e.g. SOCIOL 103 "formerly 102"); `SAME_AS` in the build script (curated, with the reason next to it); the C-prefixed form of the same subject, number and title; an id the catalog no longer lists that has the title and number of exactly one current course (`ELENG 126` -> `EECS 126`).
- An old id that has no record of its own gets a stub: `retired: true`, with the successor's title and units.
- `popularity` (integer, on every course) is the enrollment total from `data/enrollment/berkeleytime/sections.csv` (largest component per term, summed over terms and over the `sameAs` family). Only meant for ordering search results.
- REPORT.md lists the family count, the 30 most enrolled families, and old numbers that were not linked because they were reused.

## Other clean-up the build does

- `optional: true` on requirements from blocks named Honors / Optional / Recommended.
- A prose rule with a generic name ("Requirements", "Note", or the block's own name) above other rules of its block becomes a note on the next requirement instead of a self-check row (`FOLD` in the build script forces specific ones).
- A course list whose notes add "Any ECON 100-196 level course, not including ..." gets those courses added to the list (filters only combine with AND, so the range is written out).
- Lists written "Department: 101, C102, 110" are read (`named_numbers`); programs in `LENIENT_LISTS` (Statistics) also tolerate remarks in brackets and "Not ..." tails.
- Long prose is cut at a line or sentence end and finishes with "… (see the catalog for the rest)". Repeated note lines and repeated courses inside one list are dropped. `mentionedCourses` leaves out courses the text excludes and courses numbered 200+ unless the text mentions graduate courses.
- Groups carry `programType` (`major`, `joint-major`, `dual-degree`). Program names are tidied ("Chemical Engineering/Nuclear Engineering", no "Joint Major" suffix). College variants have short titles ("College of Engineering requirements (M.E.T. program)").
- The university Entry Level Writing row is `anyOf` [COLWRIT R1A, a course tagged `ELW`, a course tagged `RCA`, self-check for test scores]. The 120-unit minimum is only in the `university` group.

## Course ids

`"SUBJECT NUMBER"` using the catalog's subject code (letters and digits only): `COMPSCI 61A`, `ELENG 16A`,
`LS C70T`, `PBHLTH 142`, `MATH 51`. Normalise other spellings by upper-casing, looking the subject up in
`subjects.json` aliases, or stripping every non-alphanumeric character from the subject.
